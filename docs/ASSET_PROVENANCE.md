# Asset provenance

## Rule

An asset is publishable only when its source, rights, license, final hash, and review status are
known. Being visible on a website, present in a private prototype, generated by a model, associated
with an owned NFT, or available without a download restriction is not sufficient permission to
redistribute it.

The canonical registry source is `scripts/update_asset_manifest.ts`; it generates
`apps/web/static/assets-manifest.json`, the machine-readable publication index checked in CI.
Publication checks fail closed on a missing entry, missing or changed hash, unapproved status, or
missing license/source declaration. Human rights review remains responsible for confirming that the
declared license is correct for the path and underlying work. Running the generator is not rights
approval.

## Manifest schema

The manifest uses this minimum shape:

```json
{
  "schemaVersion": 1,
  "files": [
    {
      "path": "art/demo/example.webp",
      "sha256": "<64 lowercase hexadecimal characters>",
      "license": "CC-BY-4.0",
      "status": "approved",
      "source": "project-original"
    }
  ]
}
```

Required fields:

| Field     | Meaning                                                                |
| --------- | ---------------------------------------------------------------------- |
| `path`    | Path relative to `apps/web/static/`; no glob, URL, or absolute path    |
| `sha256`  | SHA-256 of the exact committed bytes                                   |
| `license` | SPDX expression or precise third-party license identifier              |
| `status`  | Publication review outcome; the gate currently accepts only `approved` |
| `source`  | Creator/source record or stable source reference                       |

Only `status: "approved"` permits publication. Status means that the exact hashed file is approved
to appear in this repository; it does not replace the `license` field or grant trademark permission.
An excluded candidate may be documented in review records, but the excluded binary must not be
committed merely to preserve evidence.

Brand files use `LicenseRef-TokimiSpace-Brand`, not CC-BY-4.0. Their approved status permits the
official repository and unmodified source mirrors to redistribute the reviewed bytes. Modified
products should replace them and follow [TRADEMARKS.md](../TRADEMARKS.md).

## Eligible assets

The initial public content pack is deliberately small. An asset may enter it when:

- it is project-original non-brand demo content or separately authorized third-party material;
- all source/reference inputs are eligible for public disclosure and redistribution;
- the selected license is compatible with the repository and intended distribution;
- required credit and modification notices are present;
- it does not imply official status or include a reserved project logo without separate approval;
- it passes visual continuity, safety, privacy, and hash review.

## Excluded assets

Do not publish:

- production artwork or the production content pack without separate file-level approval;
- frames, redraws, crops, close transformations, or style extractions derived from a promotional
  video;
- third-party NFT-associated characters, media, slogans, logos, or branded narrative content;
- assets copied from search results, social media, another game, a film, a website, or a stock
  service without a verified redistributable license;
- third-party fonts, music, sound effects, photos, textures, or models without exact terms and
  attribution;
- assets containing personal data, hidden metadata, private paths, unreleased material, or secrets;
- AI-assisted output whose inputs, tool terms, or human review cannot be documented.

Owning or controlling access to a token does not by itself prove authority to relicense underlying
art, brand, or derivative content under Apache-2.0 or CC-BY-4.0.

## Review workflow

1. Place a candidate outside distributable paths.
2. Record creator, source, date, tool/process, input rights, and intended license.
3. Remove private metadata and verify there is no excluded visual or textual content.
4. Review third-party terms and attribution obligations.
5. Export the final web asset and calculate SHA-256.
6. Add or update the reviewed registry entry in `scripts/update_asset_manifest.ts`, then regenerate
   the manifest with `deno task assets:update`.
7. Review the generated manifest diff and run publication and asset checks.
8. Have a maintainer approve the publication status and license before merge.

Creator, date, tool/process, input-rights, and reviewer evidence may be retained in the maintainer's
rights-review record outside this repository; the public manifest is deliberately a minimal
publication index. An asset must not be added when that evidence cannot be produced for review.

Any byte-level change requires a new hash and renewed review. Converting a blocked asset to another
format does not clear its rights.

## Attribution

For CC-BY-4.0 project content, a reasonable credit is:

> “Asset name,” TokimiSpace contributors, from Darkforest Web, CC BY 4.0; modified/unmodified.

For approved third-party material, use the exact credit required by its source license and repeat it
in [Third-party notices](../THIRD_PARTY_NOTICES.md) when appropriate.
